RTH_OUT · C & C++ 双语言输出层

从裸金属到现代 C++
同一套输出哲学

rth_out.c 是一个无 include、无 typedef、无 libc 的 C 语言输出原语层， 覆盖 Windows、Linux、macOS、FreeBSD 等平台，直接通过系统调用或 Win32 API 完成写入。
rth_out_pro.cpp 在其之上构建现代 C++ 输出抽象， 将运行时流式、编译期常量与高速缓冲三种能力解耦为独立模块。

THREE OUTPUT MODES

C++ 层的 三种模式

rth_out_pro.cpp 将输出能力解耦为三个可独立启用的模块，通过顶层宏精确控制编译裁剪。

runtime_normal_out

流式输出

最接近 std::cout 的使用体验，但性能高出数倍。每次 operator<< 直接触发 writer() 系统调用。

  • 手写 lltoa / ulltoa，比 sprintf 快 3-5 倍
  • 浮点 6 位小数四舍五入 + 尾零消除
  • 完整处理 INF / NaN / 负零
适用：调试日志 · 交互式 CLI · 嵌入式终端
constant_out

编译期常量拼接

允许在 constexpr 上下文中完成字符串格式化，零运行时开销。

  • constantout_t<N> 模板追踪容量
  • constexpr 版本 lltoa / ulltoa，无 UB
  • 支持 + / * / << 三种组合操作符
适用：编译期日志 · 静态资源表 · 模板元编程
runtime_fast_out

缓冲式高速输出

编译期已知容量的固定缓冲区 + 运行时流式追加，最后一次性刷出。

  • fastout_t<N> 栈缓冲区，零堆分配
  • << out 触发单次 writer() 调用
  • 每线程独立缓冲，无锁竞争
适用：高频交易日志 · 游戏引擎 · 服务端访问日志

roc_raw_write_x64.s C 层核心原语 
/* Linux x86_64：直接发起 write 系统调用，循环处理部分写入 */
static inline long roc_raw_write(long fd, const char* b, unsigned long l) {
    long total = 0, n;
    while (l > 0) {
        __asm__ volatile("syscall"
            : "=a"(n)
            : "a"(1L), "D"(fd), "S"((long)b), "d"((long)l)
            : "rcx", "r11", "memory");
        if (n < 0) return total ? total : -1;
        if (n == 0) break;
        total += n; b += n; l -= (unsigned long)n;
    }
    return total;
}

快速上手

C 层可独立使用，C++ 层通过宏开关按需裁剪三种模式。

// 编译 rth_out.c

terminal 
# Linux x86_64：无需任何 -l 链接
gcc -std=c99 -O2 -nostdlib main.c -o app

# Windows MSVC
cl /O2 /D roc_fileout main.c

# 关闭某个通道（例如不需要网络）
gcc -std=c99 -O2 -U roc_netout main.c

// 编译 rth_out_pro.cpp

terminal 
# 启用全部三模式（默认）
g++ -std=c++17 -O2 main.cpp

# 仅启用快速输出（嵌入式裁剪）
g++ -std=c++17 -O2 \
    -D rth_out_pro_constant_out \
    -D rth_out_pro_runtime_normal_out \
    main.cpp
C 层所有写入都绕过 printf / iostream 的缓冲层，直接发起系统调用。 C++ 层在此基础上叠加类型萃取与格式化，不引入任何堆分配。

从裸机到 C++，一套输出哲学

rth_out.c 把「写入」这件事还原到系统调用原语，不引入任何运行时依赖； rth_out_pro.cpp 在此基础上构建现代 C++ 的类型安全与编译期能力。 两者共享同一套平台检测与系统调用分发逻辑，从裸机固件到高吞吐服务端， 都能找到合适的输出抽象层。
